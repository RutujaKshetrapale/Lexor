# LEXOR — Comprehensive Uber Feature Parity Matrix

## 1. Document Overview & Parity Framework
This matrix evaluates the **LEXOR Smart Mobility Platform** against commercial ride-hailing feature parity (modeled after Uber), tailored for the target launch market (India: INR currency, UPI/Cash/Card payments, OTP trip verification, and commercial driver KYC).

Functional parity matters more than visual appearance: every screen and action must connect to an authoritative backend API, enforce role authorization, handle loading and error states, and have automated test evidence.

### Parity Status Definitions
- **Verified**: Fully implemented in frontend and backend, integrated, and verified with passing automated tests.
- **Implemented**: Implemented across frontend and backend contract, but pending complete end-to-end multi-service test run in a live environment.
- **In Progress**: Frontend UI or backend service partially implemented and currently being integrated.
- **Backend API Missing**: Desired commercial feature exists in frontend specification but has no backing microservice endpoint.
- **External Provider Missing**: Backend architecture ready, but requires external production credentials (e.g. Google Maps API, Twilio Production SMS, Razorpay Live keys).
- **Not Started**: Planned for future phase.
- **Not Applicable (N/A)**: Specific to non-launch jurisdictions (e.g., US-specific upfront driver destination withholding regulations).

## 3. Parity Status Categorization Summary

### A. Implemented and Verified (Core Flow Tested & Working)
1. **Rider Core Loop**: Registration (`POST /auth/register`), Login (`POST /auth/login`), Profile management, Geolocation discovery, Category catalogue inspection (`GET /ride-types`), Dynamic fare estimation, Ride Request submission (`POST /ride-requests`), Confirmed trip booking (`POST /bookings`), Real-time driver status tracking, OTP verification, Invoice & receipt view (`GET /payments/me/{id}/receipt`), and Two-sided driver rating (`POST /feedback/rides/{id}/driver-rating`).
2. **Driver Core Loop**: Registration & Onboarding checklist (`GET /drivers/me/onboarding`), License & KYC document upload (`POST /drivers/me/documents`), Vehicle registration (`POST /vehicles`), Availability duty toggle (`PATCH /drivers/me/availability`), Periodic GPS beacon (`PUT /drivers/me/location`), Incoming ride offer accept/decline (`POST /bookings/{id}/accept`), Full trip state machine (Arrived -> OTP Start -> Destination -> Complete), Cash collection confirmation, and Daily earnings display.
3. **Admin Operations Core**: Complete 12-screen Operations HQ (Executive Overview, Live Platform Dispatch, Rides Directory, Riders Administration, Drivers & KYC Moderation, Vehicle Fleet Verification, Payments & Refund Approval, Feedback Moderation, Analytics Trends & CSV Export, Service Health Monitor, Audit Logs, and Dynamic Operational Settings).
4. **Security & Cryptographic Boundary**: Fail-secure startup on missing JWT secret (>= 32 chars enforced across both Spring Boot and .NET), zero hardcoded secrets in production code paths, elimination of frontend mock admin token fallback, RBAC enforcement on all administrative endpoints.

### B. Implemented (Awaiting Full Multi-Service Environment Integration)
1. **Scheduled Rides**: Booking entity supports `scheduledTime` and validates future time windows; awaiting cron daemon runner in production deployment.
2. **Trip Sharing Expiring Links**: Frontend share action generates deep link; token expiration enforced via booking UUID query parameter.

### C. Backend API Dependency / External Provider Missing
1. **Production SMS OTP Delivery**: Twilio sandbox configured; requires production Twilio Account SID & Auth Token to deliver SMS to physical SIM cards.
2. **Push Notifications (FCM)**: Firebase Cloud Messaging sandbox project configured; requires production `google-services.json` / server key for mobile push notifications.
3. **Razorpay Live Processing**: Sandbox test keys configured; requires production business KYC and Live Razorpay Webhook secret for live currency charges.
4. **Google Maps / Mapbox Commercial Tiles**: Vector and OpenStreetMap engine functional with native browser geolocation; commercial Mapbox API token required for high-resolution 3D tiles.

### D. Not Applicable (N/A) to Launch Market
1. **Upfront Destination Withholding**: Not applicable under Indian mobility regulations; drivers are presented with pickup location and approximate fare breakdown.
2. **US-Specific Carpool Regulations (UberPool / HOV rules)**: Lexor launch focuses on Go, Premier, XL, and Green categories in Indian urban centers.
